What's in this mockup

  • Column grid: [24px_1fr_140px_140px_120px_60px] — checkbox · title (with category dot, preview, notable star inline) · position · folder · last edited · row actions
  • Sortable headers: Title and Last edited highlighted as sort columns. Click toggles asc/desc. Default = Last edited ↓.
  • Filter chip row: Position / Notable / Equipment / category chips. Active filters get an orange tint with × to clear individually. "Clear all" rightmost.
  • Row click → /worklog/notes/[id]. Hover reveals two icon buttons (Open, More menu).
  • Bulk-select: top toolbar transforms (orange-tinted). Move / Mark notable / Tag / Category / Delete. ESC or close-X clears selection.
  • No date grouping — flat sortable list.

Open questions (answer before I scope code)

  1. Should rows be a real <table> or stay as flex/grid divs? Native semantics + sortable column accessibility argue for table; CSS flexibility argues for grid divs. I lean grid divs (current pattern in your codebase).
  2. What does /worklog/notes/[id] actually look like? Full-screen reader (max-w-3xl prose centered) with a back-arrow header? Or a half-page modal?
  3. Grid view in the toolbar — ship now (placeholder routes to grid layout), or just put the toggle in v1 with the second mode disabled until next sprint?
  4. Position column when a note has none — show "—" / "No position" / italic "Unassigned"? I went with "No position" but Drive uses "—".
  5. Folder column when unfiled — "Unfiled" italic vs blank? I used italic; Drive uses blank.
  6. Title cell preview — keep the inline "— preview…" snippet, or drop it for cleaner columns? Trade-off: density vs scannability.
