# 0012 — W2.1: DnD Context Placement and Sortable Tree Strategy

**Status:** Proposed  
**Date:** 2026-05-25  
**Deciders:** Sory, Rex (Lead)

## Context

Sprint W2.1 adds drag-and-drop reorder and reparent for worklog notes and folders.
Two architectural decisions were debated during planning:

**AD-2**: Where to mount the single `<DndContext>`?
Options: (A) Inline in `worklog-page.tsx`, (B) Extracted `WorklogDndProvider` wrapper component.

**AD-4**: How to structure the sortable folder tree?
Options: (A) Nested `SortableContext` per folder (mirrors the visual tree), (B) Single flat list with depth metadata.

## Decision

**AD-2 → Option B**: `WorklogDndProvider.tsx` wraps the 3-pane grid.  
**AD-4 → Option B**: Flat list + depth metadata, single `SortableContext`.

## Consequences

### AD-2 Pros
- DnD logic (sensors, event handlers, overlay) is isolated from the 557-line orchestrator
- `worklog-page.tsx` stays focused on layout and selection state
- `WorklogDndProvider` can be conditionally removed/stubbed in tests

### AD-2 Cons
- Extra file and import indirection
- The provider calls `useWorklogData()` and `useWorklogFolders()` for ghost lookups — these queries are already mounted by consumers, so no new network requests, but it is an extra hook invocation

### AD-4 Pros
- One `SortableContext` = one drop target registry; simpler collision detection
- Avoids @dnd-kit's documented limitation with nested SortableContexts and cross-container drag
- `flattenFolderTree` (pre-existing utility) provides the ordered list at zero cost

### AD-4 Cons
- Drag-across-parent-folders is silently blocked at the `onDragEnd` level (same parentId check), which may surprise users expecting visual reparenting via DnD
- Visual tree rendering remains recursive (unchanged); only the DnD overlay is flat
