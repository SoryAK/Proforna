## Last Completed Step
Three back-to-back fixes on the folder-tree UX:

1. **Auto-expand on subfolder create** — in `worklog-folder-tree.tsx`, wrapped the
   `onCreate` callback in a `handleCreate(parentId)` helper that adds `parentId`
   to the `expanded` Set *before* delegating to the parent. Result: when you
   create a subfolder via kebab → "New subfolder", the parent now auto-opens so
   the new child is immediately visible.

2. **Kebab silently not opening** — `DropdownMenuTrigger` had
   `onClick={(e) => e.stopPropagation()}`. base-ui's `Menu.Trigger` opens via
   its own internal `onClick`; React last-write-wins clobbered it, so the menu
   never opened (no error, no popup). Replaced with `onMouseDown` (which
   base-ui doesn't use for opening). New rule recorded in user memory.

3. **Kebab/folders invisible in the embedded worklog** — the compact rail
   (`<WorklogPage compact />` inside `job-map.tsx`) only renders a single
   "Unfiled" icon — folder list, kebab, and "+ New folder" header all live in
   `!compact` branches. Plus the embed surface uses `z-[1300]` and base-ui
   Popover/Dropdown Positioners were at `z-[1100]`/`z-50`, so even when
   triggered the popups rendered *behind* the embed.

   Fix: in compact mode the tree now renders **two stacked icons** (Unfiled +
   Folders). The Folders icon opens a base-ui Popover flyout (`side="right"`,
   `w-64`, `z-[1400]`) containing the full tree, "+" new-root button, and
   all kebab actions. To make those popups actually visible, bumped both
   Positioners globally to `z-[2200]` — above the embed (1300) but below
   nothing important (dialogs are 2100/2110 but dropdowns are expected to
   render above dialogs anyway).
