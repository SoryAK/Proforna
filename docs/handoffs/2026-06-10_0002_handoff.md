## The "Live" Context

- **Outcome contract**: `decideShareOutcome(error)` → `"shared" | "cancelled" | "downloaded"`. Strict `error === null` for success (so `throw undefined` routes through downloaded), `name === "AbortError"` for cancellation (covers both `DOMException` and plain `Error` variants).
- **Capability gate**: `canShareFiles()` is SSR-safe and probes `navigator.canShare({ files: [<probe File>] })` — Firefox desktop fails this check even though it exposes `navigator.share`.
- **UI rule**: Share menu item is rendered **unconditionally**; the gate runs at click-time inside `shareWorklogs`. On unsupported browsers the user gets a sonner toast — *"Sharing isn't supported on this browser. The file was downloaded instead."* — and the file downloads anyway.
- **Cancellation is silent** (`outcome === "cancelled"` → no toast). User dismissed the share sheet on purpose; no need to nag.
- **PowerShell unicode hazard**: `git commit -m "...\u2014..."` doesn't decode unicode escape sequences. Phase 2 commit subject was amended once because of this. Always plain ASCII in commit subjects, or `git commit --amend` after the fact.
- **Manual + ADR markdown lint warnings** (MD040 on the Implementation Layout tree-fence + MD060 on the original config table) are **pre-existing**, not introduced by Phase 3 edits.
