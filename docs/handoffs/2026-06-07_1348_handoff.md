## The "Live" Context

- **URL contract** (memorize this):
  - `/worklog/notes` — drawer closed
  - `/worklog/notes?focus=<id>` — drawer open, read mode
  - `/worklog/notes/[id]` — full-screen reader (Edit button on drawer routes here)
  - All other params (`folder`, `view`, etc.) round-trip lossless via `URLSearchParams`.
- **Setter pattern:** `router.replace(href, { scroll: false })`. Never `router.push` for `?focus=`. Back-button must escape the whole preview model, not flip through preview history.
- **Drawer is NOT a Dialog primitive.** Plain styled container + `useEffect` window-level keydown for Esc. Dialog focus-trap + body-scroll-lock fights "list keyboard nav must keep working while drawer is open."
- **`<WorklogNoteReadView>` is shared by drawer + full-screen route.** Do NOT fork. One renderer, two surfaces.
- **Delete from drawer:** `router.replace` to clear `?focus` FIRST, THEN fire delete mutation. Reverse order causes "note not found" flash.
- **What was deliberately NOT migrated:** `?focusEquipment=` and `?focusPosition=` on the legacy `/worklog` route. Those are list-filter intents (filter list by entity X), semantically opposite of single-note `?focus=` (open drawer for note X). Allowlist of single-note callers only.
- **`new=1` companion param** is documented in ADR-0015 + UI graph as the disambiguator for Quick Capture handoff vs row click. Currently used by Quick Capture; the row-click path leaves it absent.
- **Recently-rejected approach:** reusing the existing `<WorklogNoteReader>` (edit-mode component) inside the drawer. Tempting because it already exists, but it mounts Tiptap, runs autosave, and hits the documented draft-flush race on unmount. Built a separate static reader instead.
