## Last Completed Step

All three ADR-0016 polish items resolved. Two real fixes shipped, one was a no-op once verified.

- **Item #3 — duplicate `link` Tiptap warning** (commit `fdb7d34`):
  - Tiptap 3 `StarterKit` ships its own `Link` extension. `worklog-editor.tsx` and `rich-text-editor.tsx` both import `@tiptap/extension-link` and call `Link.configure(...)` for custom new-tab / nofollow behavior, triggering `Duplicate extension names found: ['link']` on every editor mount.
  - Fix: `StarterKit.configure({ link: false })` at all three callsites (SCHEMA_EXTENSIONS + useEditor in worklog-editor.tsx, and the bare-StarterKit in rich-text-editor.tsx). Custom `Link.configure(...)` retained — it carries real product behavior (`target: "_blank"`, `rel: "noopener noreferrer nofollow"`, `openOnClick: false`).
  - Verified: starter-kit's d.ts confirms `link: Partial<LinkOptions> | false` is the official disable API. Browser console captured **zero warnings** on editor mount.

- **Item #2 — `?focus=` deep-link bug on dedicated reader** (commit `8e93b59`):
  - Real bug, not just verification. Three callsites (`mention-node-view.tsx:58`, `worklog-backlinks-panel.tsx:77`, `worklog-note-view.tsx:470`) built `${pathname}?focus=<entityId>`. On `/worklog/notes` (list view) this produces `/worklog/notes?focus=<id>` and the drawer opens. On `/worklog/notes/<currentId>` (dedicated reader) this produces `/worklog/notes/<currentId>?focus=<otherId>` — and the page only consumes the path `id`, so the click was silently dead.
  - Fix: new pure helper `buildWorklogFocusHref(pathname, entityId)` at [`src/lib/worklog/focus-href.ts`](../../src/lib/worklog/focus-href.ts). List → `?focus=`, reader → swap path id, anywhere else → list + `?focus=`. Five-case unit test (list, reader, /worklog home fallback, unrelated route fallback, trailing slash).
  - Wired in at all three callsites. Browser smoke test pivoted from `/worklog/notes/<crusher>` to `/worklog/notes/<packer3>` via @worklog chip click.
  - **369/369 tests pass** (was 364 + 5 new).

- **Item #1 — Backlinks panel in edit mode** (no-op):
  - Premise was wrong. `WorklogBacklinksPanel` is rendered **outside** the editMode ternary at [worklog-note-reader.tsx#L464](../../src/components/worklog/worklog-note-reader.tsx#L464), so it already appears in both modes on `/worklog/notes/[id]`.
