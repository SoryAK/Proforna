## The "Live" Context

- `deriveWorklogLabel` is the **single source of truth** for worklog display text across mention-search, backlinks, and the migration walker. Any future surface that renders a worklog reference must route through it.
- Picker `OR` clause uses `as const` on the `mode: "insensitive"` literal to keep the Prisma TypeScript narrowing happy.
- Migration script is **idempotent** — `result.doc === input` when nothing changes, so `prisma.workLog.update` is skipped. Safe to re-run.
- `MentionNode` chips store `{ entityType, entityId, label }`. The `label` is captured at insertion time and **does not** auto-refresh when the target's title changes. The migration script is the canonical pattern for fixing stale labels post-hoc; document this lifecycle in any future ADR that adds a new entity type.
