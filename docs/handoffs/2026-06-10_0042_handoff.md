## The "Live" Context

- **Two surfaces, two scopes** (ADR-0022 Addendum 2 — Architectural Reviewer Option A):
  - Toolbar `Export` → `visibleLogs` (current view), always visible, `triggerLabel="Export"`.
  - Bulk-bar `Send` → `selectedIdList` (current selection), only visible while bulk mode is active, `triggerLabel="Send"`.
  - **Both surfaces coexist** when bulk mode is active. Hiding the toolbar copy was rejected — losing "export the whole view" while a selection happens to be active is the worse trade.
- **Shared callbacks** in `worklog-notes-view.tsx`:
  - `runDownload(ids: string[])` and `runShare(ids: string[])` are both `useCallback(..., [])`. They wrap the export-in-flight gate (`exportBusy`) and the existing sonner toast pattern, so adding more destinations later (e.g. Drive) is a one-callback edit.
- **Honest cap**: server `BULK_MAX = 100` is mirrored client-side as `EXPORT_MAX_VIEW = 100`. When the current view exceeds the cap, the menu items short-circuit before the network call and toast: *"Too many notes in this view (N). Narrow your filter or use Select mode to pick up to 100."* The bulk-bar surface is naturally bounded by the user's selection so no client cap is needed there.
- **`WorklogSendMenu` props summary**: `count`, `onDownload`, `onShare`, `exporting?`, `busy?`, `empty?`, `emptyHint?`, `triggerLabel?` (default `"Send"`), `triggerIcon?`, `align?` (default `"end"`), `className?`. Disabled = `busy || exporting || empty`. Trigger label drops the format suffix when empty (`${triggerLabel}${empty ? "" : (count > 1 ? " as .zip" : " as .md")}`).
- **base-ui menu reminder**: `DropdownMenuItem` uses `onClick`, NOT `onSelect`. Item closes by default (`closeOnClick: true`). Stuck to this in `worklog-send-menu.tsx`.
- **Drive integration scope (ADR-0023, next session)**:
