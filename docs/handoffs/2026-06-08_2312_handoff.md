## The "Live" Context

**Schema discovery worth remembering:**
`prisma/schema.prisma → WorkLog` already had `externalSource` + `externalId` + `@@unique([userId, externalSource, externalId])` BEFORE Sprint 6B. **Zero migration was needed.** Always grep for the column you think you need before generating a migration. The `WorkLogImport.sourceType` schema comment also already listed `"notion"` as a planned source — the schema was designed for this exact case.

**Idempotency contract (re-usable for Sprint 6C):**

- Dimension: `(userId, externalSource, externalId)`
- Pattern: check first via `findUnique`, if hit → `{ status: "skipped" }`. If miss → transactional create. P2002 race → re-read winner row, return `{ status: "skipped" }`. Never throw.

**Convention crystallized this sprint:**

- Pure converter at `src/lib/worklog/import/<provider>-to-pm.ts` mirrors `markdown-to-pm.ts` / `html-to-pm.ts` — same `ImportResult { contentJson, plainText, droppedBlocks }` shape.
- SDK wrapper at `src/lib/integrations/<provider>-client.ts` keeps the converter SDK-agnostic.
- Picker UI at `src/components/integrations/<provider>-import-dialog.tsx` mounted from `IntegrationsSection`.
- Routes at `/api/integrations/<provider>/{pages,import}/route.ts`.
- Auto-create per-user folder named **"Imported from `<Provider>`"** via `ensureImportFolder()`.
- Hard caps: list ≤ 100, blocks/resource ≤ 1000, batch ≤ 25.

**Recently-rejected approaches (do NOT retry):**

- Spread-and-override `buildWorkLogImportRecord` output to bypass `sourceType` validation. Refactored to extend the helper natively.
- Parallel per-page block fetching. Notion 429s aggressively — sequential is correct.
