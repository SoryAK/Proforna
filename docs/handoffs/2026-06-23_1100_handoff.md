## 5. Unresolved Blockers

Four real issues surfaced during the audit — none break the prototype but all want v2 attention:

- **Cross-file trap unverifiability.** When a `knownTrap` describes behavior in files *other than* `entryPoint.primaryPath`, the model returns `lineRef:null` and the trap drops. 3/19 traps in the baseline hit this (one in `worklog-draft-system/trap[3]` AssetPicker auto-tag merge anchored to `use-autosave.ts`; two in `tiptap-yjs-integration` with multi-file plain-text-walker behavior). Slice manifests should split multi-file traps into per-file anchors in v2.
- **`stillValid:false` semantic conflation.** A `false` verdict can mean either real drift OR model anchoring failure. Reviewers must read evidence + checklist before trusting any STALE. v2 should add an explicit `out-of-scope` / `ambiguous` distinction.
- **Slice manifest quality issue (surfaced, not new):** `docs/c-yard/worklog-editor.json` `procedure-doc-schema` entryPoint points to `src/lib/worklog/procedure/schema.ts` which **does not exist**. 3 traps in that entryPoint dropped with `ENOENT`. Either the slice needs updating, the file was renamed/moved, or the entryPoint should be removed. Not session-blocking — orchestrator handles the case cleanly with a `file not readable` drop reason.
- **Context window sizing.** `num_ctx: 8192` overflowed silently on the 610-line `worklog-editor.tsx` (all 4 traps returned `{"` and parse-failed in <1.5s). Bumped to 16384 for this slice. Adaptive ctx-sizing (e.g. `num_ctx = max(8192, 2 * promptTokens)`) is a v2 robustness fix.
