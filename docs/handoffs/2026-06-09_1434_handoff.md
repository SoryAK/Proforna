## The "Live" Context

- `WorkLog.linkedNoteIds` is **replacement** semantic (chip removal removes the link), unlike `assetIds` which is **additive** (mentions only ADD; manual entries persist).
- Skip-if-equal guard via `arraysEqualAsSets` is shared between both columns. The PUT route's `writeAssetIds` / `writeLinkedNoteIds` flags conditionally spread the column into the update payload — so a no-op autosave does NOT churn the GIN index.
- Self-loop guard at write time: `linkedNoteIds.filter(id => id !== currentLogId)`. Picker also passes `&excludeId=<currentLogId>` for defense in depth.
- `MentionNode` is now an extension with `addOptions(): { currentLogId: null }`. The `addProseMirrorPlugins` hook calls a factory `buildMentionSuggestion(this.options.currentLogId)` rather than the previous module-level const.
- ProseMirror inline-atom mentions live inside `paragraph.content`, NOT at the doc root. The walker in `extractMentionEntityIds` recurses; ad-hoc walkers for the same data would miss them.
- Worklog label derivation (used in mention-search picker, backlinks list, and the orphan-detection cache) = first non-empty plain-text line of `contentJson` truncated to 80 chars, falling back to the workday date `YYYY-MM-DD`. The logic is duplicated in `mention-search/route.ts` and `backlinks/route.ts` — kept inline until rule-of-three triggers extraction.
