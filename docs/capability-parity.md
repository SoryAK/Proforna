# Curated capability parity

The local backup is a requirements source, not an implementation source.
Proforna preserves valuable career outcomes while replacing duplicate models,
route-owned policy, and experimental machinery.

## Product spine

| Outcome | Proforna capability | Priority |
| --- | --- | --- |
| Own career history | Enriched Work Map, geography, media, provenance | Core |
| Capture ongoing work | Worklog and fact proposals | Core |
| Present experience | Resume variants, revisions, PDF/DOCX | Core |
| Share selectively | Interactive projections and publications | Core |
| Find and pursue work | Opportunities, applications, interviews, offers | Core |
| Maintain relationships | Contacts and approved outreach | Core |
| Keep source material | Document vault and imports | Core |
| Recover and leave | Full portable export and restore | Core |
| Learn from outcomes | Privacy-minimized publication analytics | Core |

## Consolidations

- File resumes and profile-driven resumes become variants and immutable
  revisions. They do not source the Interactive Resume.
- Rich work history, the geographic Work Map, galleries, milestones, and the
  recruiter portal become Work Map roles, snapshots, and publications.
- Current position and work history use one career-fact model.
- Recruiter contact forms and submissions use the opportunity inbox.
- AI features use one governed agency layer instead of route-specific calls.

## Deferred until validated

- Building footprints and indoor maps
- Recruiter cookie CRM
- Interview video rooms
- Standalone personal inventory outside role-specific equipment and galleries
- Document RAG and vector infrastructure
- Worker-rights and broad research surfaces

Deferred capabilities may return only when they improve evidence quality,
career decisions, or a measured external outcome.
