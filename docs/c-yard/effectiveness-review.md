## 2. The 3-layer model under test

This whole sprint converged on a framework that has to prove itself:

| Layer | What it covers | Automation ceiling | Phase 1 evidence |
| --- | --- | --- | --- |
| **L1 — Bookkeeping** | dates, fingerprints, scaffolding, file metadata | Aggressive — deterministic, no judgment | Scaffold script auto-fills L1 fields |
| **L2 — Pattern detection** | recurring traversal recipes, friction signals | Mine-and-propose — human promotes | Analyzer `--mine-traversals` flag |
| **L3 — Semantic content** | design intent, knownTraps, "accepted not regression" notes | Must stay curated — codebase can't observe its own intent | Scaffold script leaves L3 as TODO placeholders |

If the model is wrong, the symptom is one of: (a) L1 automation surfaces things humans never read, (b) L2 candidates are noise and never promoted, (c) L3 is silently auto-generated by an agent and degrades. See §4.

## 3. Hypotheses — what we expect if this is working

Each hypothesis is testable. Each has a measurement source. If we can't find evidence for or against a hypothesis at review time, that's a measurability gap — file it under §5 (Open instrumentation gaps).

| # | Hypothesis | Measurement source | Expected by Review 1 |
| --- | --- | --- | --- |
| **H1** | On surfaces with a slice, Phase 0 orientation costs ≤2 tool calls (slice read + optional escape-valve) before useful action | Chat export analyzer — count tool calls between session start and first edit on slice-covered files | ≥60% of worklog-editor sessions hit this threshold |
| **H2** | When a slice's `knownTraps` accurately describes a bug, the agent surfaces it WITHOUT having to re-derive it via codegraph | Manual spot-check — pick 3 sessions touching the autosave system, verify trap was cited not re-discovered | ≥2 of 3 |
| **H3** | Scaffold script eliminates "I don't have time to start a new slice" friction | Slice count over time; scaffold script invocations | ≥1 new slice scaffolded in the 2-week window |
| **H4** | The L1/L2/L3 split survives contact with reality — no one accidentally hand-edits a fingerprint date or expects an agent to auto-write a knownTrap | Review log for "I had to override the layer" incidents | 0 violations |
| **H5** | Slice content stays fresh — `refreshHistory[]` grows, `staleSurfaces[]` stays bounded | `git log docs/c-yard/` + read each slice's `refreshHistory[]` | At least one slice has 2+ refreshHistory entries OR every slice's lastValidatedCommit is within 50 commits of HEAD |
| **H6** | The Phase 0 slice-first rule doesn't break agent behaviour on UNCOVERED surfaces (the rule has a clean fall-through to codegraph) | Analyzer — codegraph-first rate on uncovered surfaces should stay at or above pre-sprint baseline | No regression vs Review 0 baseline |

## 4. Anti-success indicators — what would prove this is NOT working

If any of these fire, the sprint is paying maintenance tax for negative value and we need to discuss retiring or reshaping the affected piece.

- **A1.** Slice count plateaus at 1 (worklog-editor) for >4 weeks. Means the scaffold script doesn't actually lower the bar enough, or the perceived value of slices for other surfaces is too low.
- **A2.** Agent has slice in front of it and STILL falls through to codegraph for questions the slice could answer. Means slices aren't structured for retrieval, or Phase 0 rule isn't being honored, or both.
- **A3.** `refreshHistory[]` stays empty after a slice ships. Means slices age into stale folklore and no one refreshes them — exactly the failure mode the memory graph had pre-sprint.
- **A4.** Scaffold script runs once, gets ignored, slices revert to hand-authoring. Means L1 automation didn't move the needle on the actual blocker (probably L3 effort was the real bottleneck).
- **A5.** Escape-valve audit trail (Phase 0 commit 3) never fires in observed sessions. Either no one is using slices (paired with A1/A2), or the rule isn't being applied.
- **A6.** Someone hand-edits a slice's `lastValidatedAt` to backdate it. Means the L1/L2/L3 split is being violated — humans should not touch L1.
- **A7.** Three or more weekly workflow reviews in a row with "no new evidence to log here." Means the system is invisible — either inert or unobservable — which is equally bad.
