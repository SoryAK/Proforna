# Feature Documentation

Each feature gets its own `.md` file in this folder following a standard template.

## File naming
`<feature-slug>.md` — lowercase, hyphen-separated (e.g. `job-map.md`, `career-model.md`)

## Template sections
| Section | Purpose |
|---------|---------|
| **Overview** | What the feature does, where it lives in the app |
| **Test Plan** | Manual and automated test steps |
| **Known Issues** | Current bugs, edge cases, quirks |
| **Changelog** | Date-stamped log of changes |

## Workflow
1. When a feature is added or significantly changed, create/update its doc
2. When a bug is found, add it to **Known Issues** with reproduction steps
3. When a bug is fixed, move it from Known Issues to Changelog with the fix date
